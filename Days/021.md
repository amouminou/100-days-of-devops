# Day 21 — Install Git & Create a Bare Repository (news.git)

## 1) Install Git using yum

Log in to the storage server and run:

```bash
sudo yum install -y git
```

Verify the installation:

```bash
git --version
```

---

## 2) Create the bare Git repository

Navigate to `/opt` and initialize a bare repository named `news.git`:

```bash
cd /opt
sudo git init --bare news.git
```

---

## 3) Verify the repository

Confirm the repository was created successfully:

```bash
ls -l /opt
```

You should see `news.git` listed. To verify it is a bare repository:

```bash
cd /opt/news.git
ls
```

Expected output includes files like:

```
HEAD
branches
config
objects
refs
```

---

## ✅ Result

- Git installed via `yum` ✅
- Bare repository created at `/opt/news.git` with the required name ✅

---

## 🔧 Why use a bare repository?

- Acts as a central remote repository for collaboration.
- Multiple developers can safely push and pull.
- Prevents accidental file edits on the server (no working tree).
- Best practice for Git servers and CI/CD systems.

---

## 📌 Key takeaways

- A **bare repository** has **no working directory** — it only stores Git metadata.
- You cannot edit files or make commits directly inside a bare repo.
- Use bare repositories as central/shared remotes; developers clone, commit locally, and push.
- Create one with `git init --bare repo-name.git` (convention: end with `.git`).

**One-liner:** Bare repositories store code history and enable collaboration — they are not for development.

# Setting up PHP 8.3 with Nginx on EL9

## 1. Context and Requirements

**Goal:** Deploy a PHP-based web application on app server 2.

**Requirements:**

- Nginx running on port `8093` with document root `/var/www/html`.
- PHP-FPM 8.3 installed and using the Unix socket `/var/run/php-fpm/default.sock`.
- Configure Nginx and PHP-FPM to communicate through this socket.
- Test the setup using `curl http://stapp02:8093/index.php`.

## 2. Understanding the Components
### 2.1 Nginx

High-performance web server, often used as a reverse proxy.

Serves static files directly and forwards PHP requests to PHP-FPM.

### 2.2 PHP-FPM

FastCGI Process Manager for PHP.

Handles PHP execution outside of Nginx.

Can communicate with Nginx via TCP port or Unix socket.

Using Unix sockets is faster and more secure for local communication.

## 3. Installing PHP 8.3 on EL9
### 3.1 Why Remi Repo?

Default repositories on EL9 typically include older PHP versions (like PHP 8.0).

Remi repo provides up-to-date PHP versions, including 8.3.

### 3.2 Steps

Check EPEL (Extra Packages for Enterprise Linux):

```bash
sudo yum install -y epel-release
```

Already installed on your system (epel-release-9-10.el9.noarch). ✅

Install Remi repo for EL9:

```bash
sudo yum install -y https://rpms.remirepo.net/enterprise/remi-release-9.rpm
```

Reset default PHP module and enable PHP 8.3:

```bash
sudo yum module reset php -y
sudo yum module enable php:remi-8.3 -y
```

Install PHP 8.3 + PHP-FPM:

```bash
sudo yum install -y php php-cli php-fpm php-mbstring php-mysqlnd
```

Verify PHP version:

```bash
php -v
```

Should output something like PHP 8.3.x (cli).

## 4. Configuring PHP-FPM

Unix socket configuration:

By default, PHP-FPM uses a TCP socket or a different socket path.

We need: `/var/run/php-fpm/default.sock`

Steps:

```bash
sudo mkdir -p /var/run/php-fpm
sudo vim /etc/php-fpm.d/www.conf
```

Modify `/etc/php-fpm.d/www.conf`:

```ini
listen = /var/run/php-fpm/default.sock
listen.owner = nginx
listen.group = nginx
listen.mode = 0660

user = nginx
group = nginx
```

`listen.owner` & `listen.group` ensure Nginx can access the socket.

`listen.mode = 0660` allows read/write for owner/group only.

`user` & `group`: The PHP-FPM worker processes run as `nginx` for security.

## 5. Configuring Nginx

Install Nginx (if not installed):

```bash
sudo yum install -y nginx
```

Configure to listen on port 8093 and forward PHP requests: edit `/etc/nginx/conf.d/default.conf` and add:

```nginx
server {
    listen 8093;
    root /var/www/html;
    index index.php index.html index.htm;
    server_name stapp02;

    location / {
        try_files $uri $uri/ =404;
    }

    location ~ \.php$ {
        include fastcgi_params;
        fastcgi_pass unix:/var/run/php-fpm/default.sock;
        fastcgi_index index.php;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    }
}
```

**Explanation:**

- `fastcgi_pass unix:/var/run/php-fpm/default.sock;` — sends PHP requests to our configured socket.
- `SCRIPT_FILENAME` — tells PHP-FPM which file to execute.

## 6. Start and Enable Services

Enable and start services:

```bash
sudo systemctl enable --now php-fpm
sudo systemctl enable --now nginx
```

- `--now` ensures the service starts now and on boot.

Verify:

```bash
systemctl status php-fpm
systemctl status nginx
```

## 7. Firewall & SELinux Considerations

Open port 8093 (if firewall is active):

```bash
sudo firewall-cmd --permanent --add-port=8093/tcp
sudo firewall-cmd --reload
```

SELinux: Allow Nginx to communicate with PHP-FPM socket:

```bash
sudo setsebool -P httpd_can_network_connect 1
```

## 8. Testing the Setup

From the jump host, test the site:

```bash
curl http://stapp02:8093/index.php
```

This should display the content of your `index.php`.

Test PHP info:

```bash
curl http://stapp02:8093/info.php
```

## 9. Summary

- Installed Nginx and PHP-FPM 8.3.
- Configured a Unix socket for PHP-FPM.
- Configured Nginx to serve PHP files via the socket.
- Enabled and started services.
- Tested the setup using `curl`.

This setup is production-ready and allows multiple DevOps engineers to work without modifying application files.

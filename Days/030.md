# Hard reset and force-push (safe workflow)

## Objective

Rewrite history so the repository contains only two commits:
- initial commit
- add data.txt file

> WARNING: This workflow rewrites history. Only perform on branches where force-pushing is acceptable.

## Steps (run on the Storage server)

### 1) Change to the repository
```bash
cd /usr/src/kodekloudrepos/media
```

### 2) Locate the commit for "add data.txt file"
```bash
git log --oneline
```

You should see output similar to:
```
a1b2c3d add data.txt file
e4f5g6h some test commit
i7j8k9l initial commit
```
Copy the commit hash for the `add data.txt file` commit (for example `a1b2c3d`).

### 3) Hard reset the branch to that commit
This removes all commits after `add data.txt file` and resets the working tree.
```bash
git reset --hard <commit-hash-of-add-data.txt>
```
Example:
```bash
git reset --hard a1b2c3d
```

### 4) Verify commit history
```bash
git log --oneline
```
Expected:
```
a1b2c3d add data.txt file
i7j8k9l initial commit
```
This confirms the history is now clean.

### 5) Force-push the rewritten history
Since history was rewritten, a normal push will be rejected. Force the update:
```bash
git push origin HEAD --force
```
Or, equivalently:
```bash
git push -f
```

## Final state
- Only two commits remain in history
- Working tree is clean
- Remote repository updated

Notes:
- Prefer `--force-with-lease` instead of `--force` when possible to reduce risk:
```bash
git push --force-with-lease origin HEAD
```

If you're unsure, back up the current branch first:
```bash
git branch backup-before-reset
git push origin backup-before-reset
```
